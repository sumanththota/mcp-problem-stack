MCP Security Gateway

An HTTP/JSON-RPC reverse proxy that sits in front of a downstream MCP server and enforces one rule: a tools/call whose params.name starts with admin_ must come from a caller whose bearer-token role is admin, or the gateway answers with a JSON-RPC error itself and the request never reaches the downstream server. Built as five tracer-bullet slices; slice 5 is the actual security boundary.

What this build actually had to decide

Four hard calls, grounded in the code

policy.py

The gate is one pure function

is_authorized(role, tool_name) takes two plain values and returns a bool — no request object, no httpx, nothing to mock to test it. It's wired into the tools/call branch in app.py, strictly before forwarder.forward() is ever awaited.

ADMIN_PREFIX = "admin_" def is_authorized(role, tool_name): if tool_name and tool_name.startswith(ADMIN_PREFIX): return role == "admin" return True

Everything not prefixed admin_ is allowed unconditionally — the policy scopes exactly to the task's own rule, nothing broader.

app.py — lifespan

One socket, not one per call

A FastAPI lifespan context manager opens a single httpx.AsyncClient at startup and stores it on app.state.http_client; it's closed once, at shutdown. Every forward() call reuses that same client — and its underlying TCP connection pool — instead of spinning one up per request.

@asynccontextmanager async def lifespan(app): app.state.http_client = httpx.AsyncClient() yield await app.state.http_client.aclose()

The comment in the source is explicit about why: "instead of opening a new connection pool to the downstream server on every single request."

errors.py + forwarder.py

Two tiers of "no"

Tier 1 is protocol-level: errors.py's jsonrpc_error() builds all five codes above — the gateway constructs and returns them itself, and forwarder.py never runs. Tier 2 is whatever the downstream server actually replies — forward() relays that response.json() body verbatim, success or failure, unmodified.

This gateway's tier 2 is a verbatim relay of the downstream body — not a isError: true business-result flag. That flag pattern belongs to the sibling mcp-tool-server's CallToolResult, a different project; nothing in mcp_gateway constructs or inspects an isError field.
auth.py + policy.py

Anonymous, but not exempt

A missing, malformed, or unrecognized Authorization header isn't rejected — get_role() just returns None. That None role still passes is_authorized() for any non-admin_ tool; it's only refused at the admin_ gate, where None == "admin" is false.

No blanket "must authenticate" rule was added — the task scoped the admin requirement to admin_-prefixed tools specifically, and the gate honors exactly that scope, deliberately, per the project's own grilling-pass notes in PLAN.md.
